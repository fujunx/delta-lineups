# Delta Lineups 开发文档

## 1. 项目目标

Delta Lineups 是一个面向《三角洲行动》玩家的道具点位教学网站。核心目标不是完整攻略展示，而是在对局间隙用尽可能少的操作快速完成一次点位复习。

主要使用流程：

1. 选择地图和干员。
2. 点击“查询”。
3. 从紧凑列表中选择点位。
4. 点击视频跳转到 B 站，查看对应时间点的视频（网站内不播放视频）。
5. 按固定顺序查看站位、瞄准点和落点等步骤图。

项目只保存公开教学内容和本地图片资源，不包含账号体系、多人协作、在线编辑或服务端数据。

## 2. 已确认需求

### 2.1 首期内容范围

| 类型 | 首期选项 |
| --- | --- |
| 地图 | 大坝、航天 |
| 干员 | 露娜、威龙 |
| 默认条件 | 航天 + 露娜 |
| 点位数量 | 预计几十个 |
| 视频来源 | B 站链接（仅提供跳转，不在网站内播放） |
| 步骤图片 | 每个点位 1～4 张 |

地图和干员必须通过配置扩展，不得将两个现有选项写死在页面组件中。

### 2.2 查询行为

- 地图和干员使用明确的选择控件。
- 修改选项后不立即刷新结果，点击“查询”后才应用新条件。
- 首次进入网站时默认查询“航天 + 露娜”。
- 查询成功后默认选中结果中的第一个点位。
- 没有匹配点位时显示明确的空状态，不保留上一次查询的内容。
- 当前查询和点位应写入 URL Hash，刷新页面后能够恢复，也可以复制链接直达具体点位。

### 2.3 点位信息

每个点位至少包含：

- 稳定且唯一的英文或拼音 ID
- 所属地图
- 所属干员
- 点位名称
- 一句话用途说明，例如“开局发射点西大”
- B 站视频原始地址（仅用于跳转到 B 站查看，不在网站内播放）
- 视频开始秒数
- 1～4 张有固定顺序的步骤图

后续允许增加但首期不强制展示的字段：

- 投掷方式
- 出生点或进攻方向
- 难度
- 标签
- 补充说明
- 排序权重

## 3. 技术方案

### 3.1 技术栈

- Vue 3
- Vite
- JavaScript
- Vue Router，使用 Hash History
- npm

选择理由：

- 构建结果是纯静态文件，适合 GitHub Pages。
- Hash 路由不会因刷新子路径导致 GitHub Pages 返回 404。
- Vite 能正确处理项目子路径和图片资源指纹。
- 项目规模较小，JavaScript 足够使用，避免引入不必要的工程复杂度。

除 Vue、Vue Router 和构建工具外，首期不引入状态管理、UI 组件库或请求库。组件间共享状态较少，使用组合式 API 和少量本地状态即可。

图标如有需要，优先使用打包进项目的 Lucide 图标库，不依赖运行时 CDN。

### 3.2 运行方式

开发阶段通过 Vite 本地服务运行。发布时生成静态资源并部署到 GitHub Pages。

不支持直接双击 `index.html` 以 `file://` 方式使用。该方式会受到模块加载、资源路径和浏览器安全策略限制。本地使用时应启动开发服务或静态文件服务。

### 3.3 GitHub Pages 兼容

- Vite 的基础路径需要匹配仓库名 `/delta-lineups/`。
- 页面路由使用 URL Hash。
- 图片必须经过 Vite 资源处理，不在业务代码中拼接站点根路径。
- 部署自动化将在用户确认后单独配置，不在首期业务开发中擅自修改 CI/CD。

## 4. 页面与交互设计

### 4.1 整体布局

网站采用桌面优先的“战术工作台”布局，避免首页、营销区块和多层卡片。页面为固定两栏：左栏是点位列表，右栏是点位图片（有序步骤图）。

```text
┌──────────────────────────────────────────────┐
│ 品牌 / 地图选择 / 干员选择 / 查询 / 结果数量 │
├───────────────┬──────────────────────────────┤
│ 点位列表      │ 图片（有序步骤图）           │
│               │                              │
│ 点位名称      │ 01 站位  02 瞄准点  03 落点  │
│ 一句话说明    │ （点击图片查看全屏）         │
│               │   [ 视频：在 B 站打开 ]      │
└───────────────┴──────────────────────────────┘
```

布局原则：

- 筛选条件始终可见，不需要返回上一页。
- 页面固定为“点位列表 / 图片”两栏结构，任何屏幕分辨率下都不改变；宽度不足时压缩右栏图片区域的宽度。
- 点位列表保持紧凑，以扫描效率为主。
- 视频不在网站内播放：仅提供一个跳转到 B 站的公链入口，点击后在新标签页打开。
- 步骤图片保持顺序，缩略图不得通过裁剪隐藏关键画面。
- 切换点位时只更新右栏，不进行整页跳转。

### 4.2 目标分辨率

无论屏幕分辨率如何，页面始终保留“点位列表 / 图片”两栏结构。宽度不足时不改变两栏，而是压缩右栏图片区域宽度，左栏列表保持相对稳定。

主要验收尺寸：

- 3440×1440：两栏布局，充分利用横向空间，同时限制图片过度放大。
- 2560×1440：两栏布局，适当压缩左栏列表宽度。
- 1920×1080：两栏布局，右栏图片区域进一步压缩。
- 更窄窗口：仍保持两栏，右栏图片区域持续压缩，保证功能可用，但不作为首期主要视觉验收目标。

布局必须使用稳定的 Grid 轨道和最小/最大宽度，右栏图片区域应使用可收缩的弹性轨道，避免标题换行或选中状态导致页面跳动或出现整体横向滚动。

### 4.3 点位列表

每项只展示：

- 点位名称
- 一句话用途
- 可选的简短标签

列表需要清楚区分默认、悬停、键盘聚焦和选中状态。长标题允许换行，但不能挤压操作区域或覆盖其他内容。

### 4.4 视频跳转

用户提供的链接形式类似：

```text
https://www.bilibili.com/video/BV12gA4z3ETZ/?t=7
```

处理规则：

- 保存用户提供的完整原始地址。
- 解析并保存 BV 号和 `t` 参数；`t` 代表开始秒数。
- 网站内不提供视频播放功能，不加载任何第三方播放器。
- 只提供一个可点击的视频入口，点击后在新标签页打开 B 站原始链接。
- 打开时使用原始带时间参数的链接，由 B 站按 `t` 秒数定位到开始位置。
- 链接无法解析或无效时，隐藏或禁用该入口并给出提示，不影响图片教学内容。
- 不截取、托管或离线缓存 B 站视频，也不在业务代码中拼接站点根路径。

### 4.5 图片查看

右栏为主体图片区域，按固定顺序展示当前点位的 1～4 张步骤图：

- 图片严格按照内容配置中的顺序展示。
- 缩略图使用完整画面，不进行中心裁剪。
- 点击图片进入全屏预览。
- 全屏预览支持上一张、下一张、关闭、滚轮缩放和拖拽查看。
- 键盘支持 `Esc` 关闭、左右方向键切换。
- 显示当前序号，例如“2 / 4”。
- 原图加载失败时显示错误状态，并允许重新加载。

## 5. 视觉方向

整体采用以白灰为主的浅色战术终端风格：浅色中性背景、清晰分区、较高信息密度，并用信号黄和警示橙区分主要操作与状态。

设计约束：

- 整体以白色和灰色为主色调：页面背景使用浅灰，内容面板使用白色，通过细边框与轻阴影表达层级。
- 不使用营销式大标题或落地页 Hero。
- 不使用大面积渐变、装饰光球和多层嵌套卡片。
- 组件圆角保持克制，优先使用细边框和色块表达层级。
- 中文正文优先使用本地系统字体，避免因外部字体 CDN 影响国内访问速度。
- 步骤图是主要视觉资产，界面装饰不得抢占其空间。
- 所有图标必须有可访问名称或悬停提示。

## 6. 内容组织方案

### 6.1 推荐目录

开发时建议按职责组织代码，点位内容与通用组件分离：

```text
src/
├── components/
│   ├── filters/
│   ├── point-list/
│   ├── point-detail/
│   └── image-viewer/
├── content/
│   ├── catalog.js
│   └── points/
│       └── <point-id>/
│           ├── index.js
│           ├── 01-position.webp
│           ├── 02-aim.webp
│           └── 03-result.webp
├── router/
├── utils/
└── views/
```

`catalog.js` 维护地图和干员选项。每个点位拥有独立目录和内容模块，构建时通过 Vite 自动发现，避免把几十个点位全部堆在一个巨大的数据文件中。

### 6.2 图片命名

用户提供图片时必须使用连续序号，例如：

```text
1.png
2.png
3.png
```

AI 录入时执行以下规则：

1. 按文件名前的数字确定原始顺序。
2. 检查序号是否重复、缺失或无法识别。
3. 根据图片用途重命名，并保留两位序号。
4. 在内容配置中显式写入图片顺序，不依赖运行时文件名排序。
5. 不覆盖其他点位已有图片。

推荐语义名称：

- `01-position`：站位
- `02-aim`：瞄准点
- `03-throw`：投掷动作
- `04-result`：落点或效果

图片格式可以保留用户原始格式。文件过大时再转换为高质量 WebP，转换后必须确认文字、准星和环境细节没有明显模糊。单张图片建议控制在 2 MB 以内。

## 7. AI 录入流程

用户每次提供新点位时，应同时给出：

- 地图
- 干员
- 点位名称
- 一句话用途
- 带开始时间的 B 站链接
- 使用数字编号的步骤图片

AI 的标准处理流程：

1. 检查地图和干员是否已经存在于目录配置中。
2. 校验 B 站链接，并解析 BV 号和开始秒数。
3. 按数字文件名确认图片顺序。
4. 根据画面用途生成语义化图片名。
5. 创建唯一且稳定的点位 ID；已发布 ID 不随展示名称修改。
6. 创建点位内容目录和内容配置。
7. 执行内容校验，检查必填字段、重复 ID、无效关联和图片缺失。
8. 在目标分辨率下检查列表、视频跳转入口和所有步骤图片。
9. 在交付说明中列出新增点位和验证结果。

如果用户信息缺少地图、干员、用途或无法确定图片顺序，AI 必须先询问，不得自行猜测。

## 8. 状态与路由

页面内部需要区分两组筛选状态：

- 待查询条件：用户当前在控件中选择的地图和干员。
- 已应用条件：最近一次点击“查询”后实际展示的地图和干员。

只有点击“查询”才将待查询条件应用到结果列表。

URL Hash 至少应表达：

- 当前已应用的地图
- 当前已应用的干员
- 当前点位 ID

首次访问且 URL 没有合法状态时使用“航天 + 露娜”。URL 中出现未知地图、未知干员或不存在的点位时，应回退到合法默认值，而不是显示空白页面或抛出运行时错误。

## 9. 性能与可访问性

- 只加载当前点位需要展示的图片，非首张图片使用延迟加载。
- 图片必须提供描述性替代文本。
- 所有交互控件支持键盘聚焦。
- 弹出的图片预览需要锁定背景滚动并正确管理焦点。
- 颜色不能作为选中状态或错误状态的唯一表达方式。
- 页面在常见缩放比例下不得出现内容遮挡和横向滚动。
- 不依赖 B 站以外的运行时第三方 CDN，不加载任何站点内的视频播放器。

## 10. 错误与空状态

必须覆盖以下情况：

- 当前地图和干员没有点位。
- 点位配置缺失或格式无效。
- B 站链接无法解析。
- 图片加载失败。
- URL 指向不存在的地图、干员或点位。

视频跳转失败时不能影响图片教学内容，用户仍能查看步骤图；视频入口无效时隐藏或禁用该入口并给出提示。

## 11. 首期不做

- 登录、注册和权限系统
- 服务端 API 和数据库
- 网站内的内容管理后台
- 全文搜索、标签筛选和收藏
- 评论、点赞和分享统计
- 自动下载或截取 B 站视频
- 离线缓存 B 站视频
- 多语言

点位预计只有几十个，地图和干员筛选足以满足首期检索需求。只有内容规模明显增长后再增加搜索和标签，避免提前增加维护成本。

## 12. 开发阶段

### 阶段一：工程与内容骨架

- 初始化 Vue 3 + Vite 项目。
- 建立地图、干员和点位内容模型。
- 建立 Hash 路由和 GitHub Pages 基础路径。
- 添加少量演示内容验证内容加载机制。

### 阶段二：核心查询工作台

- 完成地图和干员选择。
- 完成点击查询行为。
- 完成紧凑点位列表和选中状态。
- 完成点位详情切换与 URL 同步。

### 阶段三：媒体与图片体验

- 完成 B 站链接解析与跳转整理（不在网站内播放）。
- 完成带 `t` 参数的跳转链接生成与入口展示。
- 完成步骤图与全屏查看器。
- 完成图片加载失败与兜底提示。

### 阶段四：视觉、响应式与发布准备

- 完成战术工作台视觉样式。
- 验证 3440×1440、2560×1440 和 1920×1080。
- 完成键盘操作、焦点管理和性能检查。
- 用户确认后再配置 GitHub Pages 部署方式。

## 13. 验收标准

首期版本满足以下条件才视为完成：

- 首次进入默认展示航天 + 露娜的点位。
- 修改筛选条件后，只有点击“查询”才更新列表。
- 四种地图/干员组合都能正确查询或显示空状态。
- 点击列表项能立即更新右侧图片。
- 视频入口点击后在新标签页打开 B 站原始链接，并携带开始秒数；网站内不运行任何播放器。
- 每个点位能够显示 1～4 张步骤图，顺序与配置一致。
- 图片可以全屏查看、缩放、拖动和切换。
- 刷新具体点位链接后能够恢复当前内容。
- GitHub Pages 子路径下资源和路由工作正常。
- 3440×1440、2560×1440 与 1920×1080 下保持两栏，无重叠、溢出或明显空间浪费。
- 点位内容异常不会导致整个页面不可用。

## 14. 后续扩展原则

- 新增地图或干员只修改内容配置，不修改筛选组件结构。
- 新增点位以独立目录添加，不修改其他点位文件。
- 视频仅作为跳转到 B 站的入口，不引入站内播放或本地视频。
- 搜索、标签、收藏和离线能力依据实际内容规模增加。
- 不为了尚未出现的需求引入后端或复杂状态管理。

## 15. 版本控制与提交约定

- 由 AI 自主判断何时进行 git 提交，当条件合适时直接执行 commit，无需等待用户逐次确认。
- 判定的合适时机：完成了有意义的、可工作的阶段成果、修复了某个缺陷、或完成了文档中约定的一个明确条目。
- 不要求每次改动都提交，也不要求一次性完成整个项目后才提交；碎片化改动可累积到有意义的节点再提交。
- 提交前应保证该次改动处于可用状态（至少能够正常 build），避免提交会破坏构建的半成品中间态。
- 提交信息应简洁描述该次改动的目的，中文或英文均可。
- 仅执行本地 commit，不擅自进行未经用户确认的推送（push）、打标签（tag）或修改 CI/CD。
